# プロダクト要件定義 — 100 Knocks Trainer

## 1. 概要

**対象者**: Python/SQLによるデータ加工・前処理を実践的に学びたい個人。
**利用環境**: 自分のPC上でアプリを起動し、localhostのブラウザで利用。クラウド接続・アカウントは不要。
**教材**: データサイエンティスト協会の「データサイエンス100本ノック（構造化データ加工編）」を使用。公式教材はPython・SQL・Rに同内容の問題を用意しているが、本アプリではPython/SQLを対象とする。

### 成功体験

学習者が1問を選んでコードを記述し、実行結果を見ながら修正、正解したら次の問題へ進める。アプリを閉じてもコードと進捗が残る。PythonとSQLで同じ問題に再挑戦できる。

## 2. Must / Should / Later

### Must（MVP）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-01 | 問題を一覧から選ぶ | 収録済み問題のID・題名・ステータスから選択できる |
| F-02 | Python / SQL切替 | 設問は対応付けられるが、コードと達成状況は言語別に保持 |
| F-03 | 問題文表示 | 出典を明記。解答が初期表示されない |
| F-04 | コード編集 | 複数行入力でき、切替や再起動で草稿を失わない |
| F-05 | コード実行 | Python/SQLを実行し、DataFrame・表・スカラー・例外を確認できる |
| F-06 | 採点 | 実行結果と問題固有の判定条件を比較し、正解/不正解/判定保留を返す |
| F-07 | フィードバック | 正誤、理由、エラー種別、可能なら不一致箇所を簡潔に表示 |
| F-08 | 進捗保存 | 未着手/挑戦中/正解/復習対象（保留状態は別属性可）を言語別に保存 |
| F-09 | 解答履歴 | 最終コード・直近の実行/採点・初回正解日時を保持 |
| F-10 | ローカル起動 | GitHubから取得して簡単な手順で起動でき、ブラウザでlocalhostを開ける |

### Should（MVPが完成した後）

- 問題単位・カテゴリ単位の進捗ダッシュボード
- 正解数や学習時間/学習日の確認、復習フラグ
- 模範解答の段階的開示、ヒントの提示
- SQLとPythonの模範解答を並べて比較
- 初回正解までの挑戦回数、解答履歴の閲覧
- 進捗データのエクスポート/インポート

### Later

- AIによるヒント・レビュー（採点の根拠にはしない）
- 任意データセット・問題集のプラグイン化
- 多人数・クラウド対応
- R、学習リマインダー、スマートフォン完全対応

## 3. 主要画面（MVP）

### 問題演習ページ

- 左：問題一覧（ID、進捗、カテゴリ）
- 中央：問題文、Python/SQL切替、コード編集、`実行`、`採点`、`次へ`
- 下部：実行結果タブ（表形式、標準出力、エラー、採点結果）
- 言語切替時は入力内容を永続化し、同じ問題のもう一方の言語を開く
- 採点結果は **正解（passed）/不正解（failed）/自動判定不可（manual_review）/実行エラー（error）** を区別

### 進捗ページ

- 収録問題数、Pythonで正解した問題数、SQLで正解した問題数
- 状態別・カテゴリ別進捗。両言語の正解を混ぜて「完了」とはしない
- 再学習したい問題を選べる

## 4. ユーザーフロー

1. Docker Composeで起動し、localhostを開く。
2. 問題一覧から設問を選ぶ。PythonかSQLを選択する。
3. コードを書く。明示的に `実行` すると結果がテーブル等で表示される。
4. 複数回試行できる。草稿は自動保存される。
5. `採点` を押すと同じ言語の出力が判定される。未対応問題は判定不能の旨を示す。
6. 正解時はその言語の進捗を更新。アプリ再起動後も保存される。

## 5. MVP対象問題

- 第1段階: 実在する最初の問題1件について、Python/SQLとも実行・判定可能にする。
- 第2段階: 代表的な性質が異なる3〜5問を対応（テーブル取得、フィルタ、ソート、集計等）。
- 第3段階: 最初の10問程度に拡大し、採点テンプレートを安定させる。
- 公式教材には一部、ファイルI/O・乱数・更新系の問題が含まれる。これらは後期に固有検証器を実装し、採点不可の場合はその旨を明示する。
- 公式Notebookの現物を調べるまでは、問題ID・正解条件を断定しない。

## 6. 非機能要件

- 原則完全ローカル、学習中の外部API送信なし。
- 個人利用、匿名ローカル利用。認証不要。ただし **localhost以外にサービスを公開しない**。
- 学習コード実行に時間・メモリ・出力件数の上限を設け、UIが固まらない。
- アプリを再起動・更新してもSQLiteの履歴が残る。
- 公式データに含まれるコード列、日付、NULL、重複などを極力元の型に沿って扱う。
- Windows 11 / Docker Desktop（WSL2）での起動を優先検証。macOSは後続で確認。
- READMEは非技術者でもセットアップを再現できるようにする。

## 7. 受入シナリオ（End-to-End）

1. 空の新規環境で `docker compose up --build` 相当の手順からアプリにアクセスできる。
2. Pythonで最初の問題の正解コードを実行すると期待する表が表示される。
3. 同じ設問を別の正しい書き方で回答しても正解判定される。
4. 明らかな誤答は不正解となり、SQL構文エラー/Python例外は画面に表示される。
5. SQLに不許可の更新文を送っても教材用DBを変更できない。
6. 解答後にコンテナを再起動しても回答の草稿と合格状態が維持される。
7. `docker compose down`（`-v`なし）で履歴は消えない。

## 8. 機能の境界

- 「正解」は単純な行数や出力見た目の一致だけでなく、設問の意味と判定ルールを満たすこと。ただし有限データでの検証には限界があるため、テストの保証範囲を透明化する。
- `実行` ボタンは採点にも進捗の合格判定にも影響しない。最後の実行日時の更新はよい。
- 進捗は設問×言語の単位。「一方を正解したら両方合格」にしない。

### 9.2 採点ルール

- 採点結果は `passed` / `failed` / `manual_review` / `error` の4種。
- 学習者のPython解答はPython模範解答の実行結果、SQL解答はSQL模範解答の実行結果と比較する。
- **N件表示ルール**（例: 「先頭10件表示」）：列名・列順・行数Nが一致し、各行が「件数制限を外した正しい全結果」に含まれれば `passed`。
- **順序指定なし**：行の多重集合で比較（重複は保持）。**順序指定あり**：ソートキーの順序のみ検証し、同順位内は問わない。
- DataFrameのindexは既定で比較しない。型は意味カテゴリで比較し、コード値のゼロ埋め文字列を数値化しない。
- 不一致時は「列名が違う」「行数が違う（期待N / 実際M）」「条件を満たさない行がある（例を最大数件）」など理由を表示。模範解答の全文は表示しない。
- 問題文が特定の書き方を求めるもの（例: P-009「ORをANDに書き換えよ」）も、MVPでは結果のみで判定し、その限界を問題画面に注記する。
- 問題文が列名を指定しない集計等は、列名を問わず列の位置で照合する（`column_names = false`）。採点基準は画面に注記する。
- 件数などの値を答える問題では、SQLの1行1列の結果も値として扱う。
- 正解が1つに決まらない問題（同額への別順位の割り当て、複数の最頻値など）は、理由を表示して自動採点しない。
- 問題文が許す範囲の書き方の違い（分散の ddof、対数化前の +0.5、コード値の文字列/数値、四捨五入/偶数丸め、列構成の2通りなど）は、許容する別の参照（`alternatives`）のどれかに一致すれば正解とし、画面の採点基準に明記する。
- 日時は表記をそろえて比較する（深夜0時の日時と日付は同じとみなす）。日付型を求める問題で文字列を返した場合は不正解。
- 「データを作成せよ」という問題は、画面で指定した名前の変数（Python）/ テーブル（SQL）を採点する（表示や件数の確認は採点しない）。
- 前の問題の結果を使う問題では、前の問題の模範解答でデータを用意してから実行し、用意した内容を画面に表示する。
- SQL の書き込み可能モード: 複数文・CREATE TABLE 等を実行でき、作成物は一時テーブルとして実行後に必ず取り消す。教材テーブルは変更不可。DBサーバー上のファイル入出力は不可で、COPY ... TO STDOUT / FROM STDIN を使う。
- ファイル出力の問題は、出力ファイルの文字コード・区切り文字・ヘッダの有無と内容を採点する（行の順序・数値の表記ゆれは問わない、コード値のゼロ埋めは区別）。
- 乱数を使う 089/091 は、重なり・全体との一致・比率（089）、1:1 と少数側の全件（091）という性質で採点する。

### 9.3 実行仕様

- Python：コードの最後の式の値を結果として表示・採点する（Jupyter同様）。`print` は標準出力欄。最後が式でない場合は案内メッセージを出す。利用可能な変数は公式セットアップと同じ `df_customer` / `df_category` / `df_product` / `df_receipt` / `df_store` / `df_geocode`。ライブラリは公式セットアップでimportされるもの（pandas, numpy, scikit-learn, imbalanced-learn, dateutil 等）を事前に用意。
- SQL：Phase 1は単一のSELECT文（CTE含む）のみ。教材DBは読み取り専用。
- 表示は先頭の一定行数（既定200行）に制限し、総行数と「省略あり」を明示。採点は表示制限とは別に全結果（上限付き）で行う。
- Python 3.12 + pandas 3.0.6 を使用（公式Notebookは pandas 1.5.3）。pandas 3.0 で動作しない公式解答（071/072/073/083/084/086）は3.0対応の参照解答を用意し、上流との差分を記録する。
